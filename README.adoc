= Equivalence Engine Action

Modular GitHub Action to automate codebase adaptation using the Evolution Engine and custom rulesets.

link:https://github.com/dev-centr/equivalence-engine-action/issues[Report Bug] ·

== About The Project

A generic GitHub Action to automate code adaptation using the link:https://github.com/dev-centr/equivalence-engine[Equivalence Engine] and a specified ruleset.

Keep this repository **separate** from the engine; pin versions explicitly so engine, rules, and action stay in sync (see link:COMPATIBILITY.md[COMPATIBILITY.md]).

=== Ecosystem

* link:https://github.com/dev-centr/equivalence-engine[Equivalence Engine] — The core binary that resolves and applies migration and equivalence rules.
* link:https://github.com/dev-centr/equivalence-engine-action[Equivalence Engine Action] — This repository (modular GitHub Action).
* link:https://github.com/dev-centr/equivalence-rules-code[Equivalence Rules: Code] — Rules for migrating source code between library versions.
* link:https://github.com/dev-centr/equivalence-rules-filesystem[Equivalence Rules: Filesystem] — Cross-OS path rules.

== Usage

=== Recommended: full pinning

Pin **the action ref**, **`engine-version`**, and **`rules-version`** (and optionally **`rules-repo`** if you fork rules). Defaults in `action.yml` match the row in link:COMPATIBILITY.md[COMPATIBILITY.md] for each action release tag.

[source,yaml]
----
- name: Adapt code
  uses: dev-centr/equivalence-engine-action@v2.1.1
  with:
    engine-version: v1.3.2
    rules-repo: dev-centr/equivalence-rules-code
    rules-version: v1.0.0
    from: '5.15'
    to: '6.0'
    library: 'python/PyQt'
    in-place: 'true'
----

You may pin **`engine-version`** / **`rules-version`** to a **commit SHA** instead of a tag.

=== Floating `latest` (optional)

For quick experiments you can use `uses: dev-centr/equivalence-engine-action@latest`. That only pins the **action** snapshot; you should still set **`engine-version`** and **`rules-version`** explicitly in production, or you inherit the defaults baked into that action revision (which can change when `latest` moves).

=== Inputs

[cols="1,2,1"]
|===
| Input | Description | Default

| `path` | Path to the code to adapt | `.`
| `engine-repo` | Engine repository | `dev-centr/equivalence-engine`
| `engine-version` | Engine git ref (pin in CI) | `v1.3.2`
| `rules-repo` | Rules repository | `dev-centr/equivalence-rules-code`
| `rules-version` | Rules git ref (pin in CI) | `v1.0.0`
| `library` | Library/Binding subpath (e.g., `python/PyQt`) | `""`
| `from` | Starting version/context | (Required)
| `to` | Target version/context | (Required)
| `rules-dir` | Path to rules within the rules repo (or URL) | `rules`
| `in-place` | Modify files in-place? | `true`
| `out-dir` | Output directory for transformed files | `""`
| `extensions` | Comma-separated list of extensions | `.py,.cpp,.h,.js,.ts,.astro`
|===

=== Dual Release Strategy

To maintain both original and adapted versions, use the `out-dir` input:

[source,yaml]
----
- name: Adapt code
  uses: dev-centr/equivalence-engine-action@v2.1.1
  with:
    engine-version: v1.3.2
    rules-version: v1.0.0
    from: '5.15'
    to: '6.0'
    library: 'python/PyQt'
    out-dir: 'dist/qt6'
----

See link:CHANGELOG.md[CHANGELOG.md].
